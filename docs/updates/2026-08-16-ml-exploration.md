## What was built, in priority order

**1. `detection/clustering.py` — v2 daily-pattern clustering (highest priority; most complete).** Fresh implementation (design referenced, did not extend, `detection/legacy/clustering.py`). Feature selection driven by an actual correlation matrix on real data (drops 2 of 16 `daily_features` columns for exact/near-exact linear redundancy — documented as public constants, not just comments); a coverage filter (`filter_low_coverage_days`) that excludes 24% of days in the default 18-month window because low-CGM-coverage days were forming their own spurious "cluster"; k-means as the primary algorithm plus Ward/GMM as validation-only comparisons; four independent validation checks (elbow, silhouette, block-bootstrap stability via Adjusted Rand Index, cross-method agreement) run against the owner's real Supabase data, not synthetic data. **Honest finding: the data supports k=2 (a soft "glucose control quality" gradient), not the old `detection/legacy/clustering.py` config's `n_clusters: 5` default** — silhouette and stability metrics both degrade sharply past k=2. Full write-up with real numbers: `docs/ml-notes/clustering.md`.

**2. `detection/supervised.py` — supervised models on the M2 meal-rise corpus.** New corpus-assembly step (`scripts/build_meal_rise_corpus.py`) over the existing, unmodified `detection/calibration/meal_rise_scoring.py`; a strict leakage boundary (`SAFE_FEATURES` vs. `LEAKY_FEATURES`, asserted disjoint, tested) between features computable at detection time and fields the M2 scorer only derives after knowing the label; chronological (not random) train/test split with the reasoning documented; two baselines (majority-class, hour-of-day) so a bare accuracy number isn't misleading. **Honest finding: on 1619 real labeled instances, a `class_weight="balanced"` RandomForestClassifier (0.762 accuracy) does not beat either baseline (0.789 / 0.786)** — the CGM-shape-only features available at meal-rise-detection time carry very little signal for whether/when a bolus follows. Documented as a real negative result, with a discussion of why and what a next pass should try. Write-up: `docs/ml-notes/supervised-models.md`.

**3. `apps/personal/telegram/llm_assistant.py` — LLM cause-attribution assistant, code-complete but unwired.** No live `ANTHROPIC_API_KEY` anywhere; `LLM_ASSISTANT_ENABLED` unset in every deploy target. Backend-swappable via an `LLMClient` Protocol (`MockLLMClient` for local/no-network testing, `AnthropicLLMClient` with a lazily-imported `anthropic` SDK so it never affects the cron worker's Vercel deploy bundle — `anthropic` is a new *optional* `llm` dependency group in `pyproject.toml`, deliberately not added to root `requirements.txt`). The LLM only ever sees pre-computed deterministic digest text (the same text `/today`/`/trends` already produce) — never raw CGM data or a `Storage` handle. Small, additive, backward-compatible wiring into `apps/personal/telegram/commands.py` (`ParsedCommand.raw_text`, new defaulted field) and `apps/personal/telegram/handler.py` (`llm_client: LLMClient | None = None` on `build_reply`/`process_webhook`) — every pre-existing test in `tests/personal/test_telegram_handler.py` passes unmodified, proving the addition is inert by default. Design + manual testing procedure (works today with no API key via `MockLLMClient`): `docs/ml-notes/llm-assistant.md`.

## Data note

No local parquet data exists in this environment — the Aug 2026 sync work (Phase 1 of this session) landed history in Supabase, not `data/processed/*.parquet`. Two new loader scripts (`scripts/build_daily_features_dataset.py`, `scripts/build_meal_rise_corpus.py`) query `SupabaseStorage` directly (transaction-pooler connection, short-lived, read-only) rather than going through `ingestion/view_data.py`'s parquet-only loader — this is also the architecturally-correct direction per `CLAUDE.md`'s DI guidance ("new downstream code takes a `Storage` via DI from the start"). Both scripts default to a trailing-18-month window (documented rationale: therapy-regimen drift over the owner's ~5-year CGM history would mix eras and blur genuine behavioral structure); both write gitignored outputs under `data/processed/` and `data/reports/` — nothing with personal health data is committed.
